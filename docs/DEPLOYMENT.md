# Deploying on Windows (production)

This guide installs the Hotel IT Management System on one Windows server on the hotel's network.
Staff use it from any browser on the LAN. Allow about an hour.

## 1. Server and accounts

* **Windows Server 2019/2022/2025**, or Windows 10/11 Pro for a small hotel. It must stay switched on.
  * 4 GB RAM and 2 CPU cores are enough for a few hundred users.
  * Allow disk space for evidence photos and videos: 50 GB to start.
* **A fixed IP address** on the LAN, or a DNS name such as `it-server.hotel.local`.
* **A second disk or a NAS share** for backup copies.
* **A Windows account to run the system.** This is recommended; SYSTEM also works.
  * Create a local user, for example `svc-hotelit`, with a long password that never expires.
  * It should not be an administrator.
  * The install script grants it access to the data folders.
* Install **Python 3.12 or 3.13** from <https://www.python.org/downloads/windows/>. Choose *Install for all users* and tick **Add python.exe to PATH**.

## 2. Install PostgreSQL

1. Install **PostgreSQL 16 or 17** from <https://www.postgresql.org/download/windows/>. Keep the default port 5432 and remember the `postgres` password.
2. Open **SQL Shell (psql)** and sign in as `postgres`. Run:

   ```sql
   CREATE USER hotel_it WITH PASSWORD 'choose-a-long-random-password';
   CREATE DATABASE hotel_it OWNER hotel_it ENCODING 'UTF8';
   \c hotel_it
   ALTER SCHEMA public OWNER TO hotel_it;

   -- Scratch database used only to test-restore backups (recommended).
   CREATE DATABASE hotel_it_verify OWNER hotel_it ENCODING 'UTF8';
   \c hotel_it_verify
   ALTER SCHEMA public OWNER TO hotel_it;
   ```

   `hotel_it` must own the `public` schema. Restoring a backup replaces the schema, and verification does the same in the scratch database.
3. PostgreSQL only accepts connections from the server itself by default. Keep it that way: the application runs on the same machine.

## 3. Install the application

1. Copy the project folder to the server, for example `C:\HotelIT\hotel-it-system`.
2. Open **PowerShell as Administrator** in that folder and run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -ServiceAccount svc-hotelit
   ```

   The script:
   * checks Python;
   * creates `.venv` and installs the packages;
   * creates `.env` with a new random secret key;
   * creates the uploads, backups and logs folders and restricts access to them;
   * applies the database migrations and collects static files;
   * runs the readiness check.

   On the first run it stops after creating `.env`. Fill it in (next section), then run the script again to finish.

## 4. Configure `.env`

Open `.env` in Notepad. The file holds the secret key and the database password: never email it or put it on a shared drive. Keep a copy in the hotel's password manager or safe, because it is **not** included in backups.

| Setting | Production value |
|---|---|
| `DJANGO_DEBUG` | `0` |
| `DJANGO_SECRET_KEY` | already generated by the install script |
| `DJANGO_ALLOWED_HOSTS` | names/addresses staff type, e.g. `it-server,it-server.hotel.local,192.168.1.20` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | full addresses, e.g. `https://it-server.hotel.local` or `http://192.168.1.20:8000` |
| `DJANGO_USE_HTTPS` | `1` once HTTPS is set up (section 8) |
| `HOTEL_NAME`, `HOTEL_TIMEZONE` | e.g. `Seaview Hotel`, `Africa/Nairobi` |
| `DB_ENGINE` | `postgres` |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | `hotel_it`, `hotel_it`, the password from step 2 |
| `PRIVATE_MEDIA_ROOT` | uploads folder, e.g. `D:\HotelIT\media_private` (optional) |
| `BACKUP_ROOT` | e.g. `D:\HotelIT\backups` |
| `BACKUP_COPY_TO` | second disk or NAS, e.g. `\\nas\backups\hotel-it` |
| `BACKUP_VERIFY_DB` | `hotel_it_verify` |
| `PG_BIN_DIR` | `C:\Program Files\PostgreSQL\16\bin` if `pg_dump` is not on PATH |
| `SITE_BASE_URL` | the address in notification emails, e.g. `https://it-server.hotel.local` |
| `EMAIL_*` | your mail server, if email notifications are wanted |

For the NAS share, the account that runs the tasks needs write access to it. SYSTEM uses the computer's account, `DOMAIN\SERVER$`.

Run `scripts\install.ps1` again. It finishes with the readiness check.

## 5. First administrator

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Sign in, then go to **Administration**:

1. **System Configuration:** hotel name, timezone, upload limits, ticket and procurement rules.
2. Create **departments** and **locations**.
3. Create **user accounts**. Each new user gets a temporary password and must change it at first sign-in.
4. Check **Ticket Categories**, **Task Categories**, **Service Targets** and **Asset Categories**. Sensible defaults are already installed.

Never run `seed_demo` on the live database. Demo accounts have a published password.

## 6. Scheduled tasks: server, jobs, backups

In **PowerShell as Administrator**, in the application folder:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\register_tasks.ps1 -User ".\svc-hotelit" -Port 8000
```

You are asked for the account's password. Omit `-User` to run as SYSTEM. This registers three tasks:

| Task | When | What |
|---|---|---|
| **HotelIT Server** | at boot; restarts every minute if it stops | Waitress web server |
| **HotelIT Jobs** | every 10 minutes | escalations, reminders, maintenance visits, recurring tasks, auto-close |
| **HotelIT Backup** | daily at 02:30 (`-BackupTime`) | verified backup, copy to `BACKUP_COPY_TO`, rotation |

Run the first backup now and check it under **Administration → Backups**:

```powershell
Start-ScheduledTask "HotelIT Backup"
```

To stop or start the system: `Stop-ScheduledTask "HotelIT Server"` and `Start-ScheduledTask "HotelIT Server"`.

## 7. Firewall

If staff connect straight to Waitress on port 8000:

```powershell
New-NetFirewallRule -DisplayName "Hotel IT System" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Domain,Private
```

If HTTPS is set up (next section), open 443 instead and keep 8000 closed.
Never expose the system directly to the internet. Remote staff should use the hotel's VPN.

## 8. HTTPS

Without HTTPS, passwords and evidence cross the hotel network unencrypted, where anyone on guest-adjacent networks could read them. HTTPS is strongly recommended.

The application already supports it: Waitress listens on `127.0.0.1` only, and a web server in front handles the certificate.

### Option A: Caddy (simplest)

1. Download `caddy_windows_amd64.exe` from <https://caddyserver.com/download> and save it as `C:\HotelIT\caddy\caddy.exe`.
2. Create `C:\HotelIT\caddy\Caddyfile`:

   ```
   it-server.hotel.local {
       tls internal                 # or: tls C:\certs\it-server.crt C:\certs\it-server.key
       request_body {
           max_size 1GB
       }
       reverse_proxy 127.0.0.1:8000
   }
   ```

   * `tls internal` makes Caddy create its own certificate authority. Install its root certificate (`caddy trust`, or copy the `root.crt` that Caddy prints to the hotel PCs via Group Policy) so browsers trust it.
   * If the hotel has an internal certificate authority or a purchased certificate, use that instead.
3. Run Caddy at boot with a scheduled task: `caddy.exe run --config C:\HotelIT\caddy\Caddyfile`.
4. Re-register the application tasks behind the proxy:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\register_tasks.ps1 -User ".\svc-hotelit" -BehindProxy
   ```

   With `-BehindProxy`, Waitress:
   * listens on `127.0.0.1:8000` only;
   * trusts the `X-Forwarded-Proto` and `X-Forwarded-For` headers only from this machine.

   The audit log and the login lockout therefore see each user's real IP address.
5. In `.env`, set:

   ```
   DJANGO_USE_HTTPS=1
   DJANGO_CSRF_TRUSTED_ORIGINS=https://it-server.hotel.local
   SITE_BASE_URL=https://it-server.hotel.local
   ```

   This turns on secure cookies and redirects to HTTPS. After a week without problems, also set `DJANGO_HSTS_SECONDS=31536000` so browsers refuse plain HTTP.
6. Restart: `Stop-ScheduledTask "HotelIT Server"; Start-ScheduledTask "HotelIT Server"`. Then open port 443 in the firewall.

### Option B: IIS

1. Install IIS with the **URL Rewrite** and **Application Request Routing** modules.
2. Bind the site to HTTPS with the hotel's certificate.
3. Enable the proxy under *ARR → Server Proxy Settings*.
4. Add a reverse-proxy rule to `http://127.0.0.1:8000`.
5. Add the server variable `HTTP_X_FORWARDED_PROTO=https`.
6. Raise *Request Filtering → Maximum allowed content length* to 1 GB so video evidence can be uploaded.
7. Then do steps 4–6 of Option A.

## 9. Go-live checklist

Run this and fix every **FAIL**:

```powershell
.\.venv\Scripts\python.exe manage.py preflight
```

It checks:
* debug mode, the secret key and allowed hosts;
* HTTPS;
* PostgreSQL and pending migrations;
* static files;
* the uploads and backup folders, and whether backups sit on the same disk;
* `pg_dump`, and the age and verification of the last backup;
* administrators, demo data and email settings;
* Django's own deployment checks.

Then also:
* [ ] Sign in from a staff PC with each role (admin, IT officer, manager, employee).
* [ ] Raise a test ticket with a photo from a phone.
* [ ] **HotelIT Backup** has run and shows **Verified** under *Administration → Backups*, and a copy exists in `BACKUP_COPY_TO`.
* [ ] A copy of `.env` is stored safely, away from the server.
* [ ] The restore drill in [BACKUP_AND_RESTORE.md](BACKUP_AND_RESTORE.md) has been done once.

## 10. Updating to a new version

1. Copy the new code over the application folder. Keep `.env`, `media_private`, `backups` and `logs`.
2. In **PowerShell as Administrator**:

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\update.ps1
   ```

   The script:
   * makes a verified backup, and stops if that fails;
   * stops the tasks;
   * installs packages, applies migrations and collects static files;
   * starts the tasks again;
   * runs the readiness check.
3. To undo an update, put the previous code back and restore the backup the script made (see [BACKUP_AND_RESTORE.md](BACKUP_AND_RESTORE.md)).

## 11. Troubleshooting

| Symptom | Check |
|---|---|
| Browser shows "Bad Request (400)" | The address is not in `DJANGO_ALLOWED_HOSTS`. |
| "CSRF verification failed" when signing in | Add the exact address, with `http://` or `https://` and port, to `DJANGO_CSRF_TRUSTED_ORIGINS`. |
| Page has no styling | Run `.\.venv\Scripts\python.exe manage.py collectstatic --noinput`, then restart the server task. |
| Server task keeps restarting | Run `scripts\start_server.ps1` in a window to see the error. Also look in `logs\hotel_it.log`. |
| Backup fails with `pg_dump was not found` | Set `PG_BIN_DIR` in `.env`. |
| Backup copy fails | The task account needs write access to `BACKUP_COPY_TO`. A mapped drive letter (`Z:`) does not work for scheduled tasks; use the UNC path `\\nas\share`. |
| Large video uploads fail behind IIS | Raise IIS *Maximum allowed content length*. |
| Everyone locked out after failed sign-ins | Wait for the lockout period (default 15 minutes), or have an administrator reset the password. Behind a proxy, use `-BehindProxy` so each user's own IP is used, not the proxy's. |
